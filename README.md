# «Врач» — помощник по проверке заявок

Учебный командный проект: секретарь загружает Excel, система сопоставляет препараты
с МНН, проверяет пары «препарат + диагноз», показывает категории **А / Б / В**,
основания, предупреждения, доли сумм и цветовой индикатор. Результат доступен
в карточке, разделе **«Разбор ИИ»** и скачиваемом Excel.

**Результат рекомендательный. Решение принимает человек.** При недостатке оснований
категория остаётся пустой и требуется проверка. Схему приёма, количество и
длительность лечения система не оценивает; сопоставление формы/концентрации может
давать отдельное предупреждение. Суммы и доли рассчитывает код, не LLM.

## Два варианта запуска

| Вариант | Что выполняется | Инструкция |
| --- | --- | --- |
| Локальная демонстрация без AI | `template`: синтетический справочник `demo-api-2`, шаблонные комментарии; без вызовов модели | [Установка на Windows, macOS и Linux](docs/installation.md) |
| Сборка защиты с GigaChat | `network`: один `analyze_request()` на заявку в отдельном worker, реальные ГРЛС/КР, GigaChat и Embeddings; backend-справочник отключён | [Настройка сетевой сборки](docs/network-setup.md) |

Для Docker-запуска нужны **Git, Docker и Compose v2** с поддержкой `--wait`.
Python 3.11 и Node.js нужны на хосте только для разработки; внутри образов уже
используются Python 3.11 и Node.js 22. Стек: FastAPI, Pydantic v2, SQLAlchemy 2,
Alembic, PostgreSQL 16, React/TypeScript/Vite, nginx.

Оба варианта запускаются из корня репозитория. Команды используют имена сервисов
`api`, `web`, `db`, а не имена контейнеров. В инструкциях настройки передаются
из текущего терминала; существующий `.env` автоматически не загружается.

## Входные файлы и результат

- Прежний плоский XLSX поддерживается в обоих вариантах. Четыре синтетических
  примера находятся в [data/demo/](data/demo/): `correct.xlsx`, `typo.xlsx`,
  `unknown.xlsx`, `two_diagnoses.xlsx`. Их ожидаемые результаты относятся к
  `template` с `demo-api-2`, а не к реальной медицине.
- В сетевом режиме также поддерживаются AI-книги: два листа «Заявка», «Покупки»
  либо четыре — «Заявка», «Диагнозы», «Покупки», «Связи». Точный формат задаёт
  [библиотечный парсер](ai/src/llm_rag/integration_excel.py);
  [учебные книги](ai/excel_input/) используются в приёмке. Возраст, МКБ,
  редакция КР и явные связи берутся из книги; неизвестные значения не дополняются.
- Проверки хранятся отдельно для каждой пары. Категории в JSON и справочниках —
  кириллические **А/Б/В**; латинские `A/B/V` не принимаются.
- Полный AI-результат и снимок оснований сохраняются в PostgreSQL. Повторное
  открытие карточки, AI-отчёта и Excel не вызывает модель. `COMPLETE` означает
  завершение обработки пар; успех модели и достаточность оснований проверяются отдельно.

## Доступ и ограничения

Наружу публикуется только `web`. При заполнении **обоих** `WEB_USER` и
`WEB_PASSWORD` nginx включает общий Basic Auth; `/health` открыт. Если хотя бы
одно поле пустое, Basic Auth выключен. Документация API и список заявок по
умолчанию возвращают 404. Индивидуальных учётных записей, ролей, аудита и HTTPS
в текущей сборке нет. Basic Auth по HTTP не шифрует передачу.

Внешние запросы проходят фильтрацию: передаются разрешённые МНН/диагнозы и
необходимые публичные фрагменты/метаданные источников. Файл заявки, исходные
идентификаторы, суммы, дозировка, количество, возраст и произвольный клинический
контекст в запрос модели не включаются. TLS-проверка включена. Подробнее:
[сетевая сборка](docs/network-setup.md#данные-и-сеть).

Для показа используйте синтетические заявки. Согласованной независимой клинической
приёмки нет; соответствие категорий задачам комиссии и пороги индикатора требуют
подтверждения аналитиком. Ветка содержит интеграционные исправления в `ai/` поверх
версии коллег: при сборке фиксируйте фактические SHA, а не только исходный `8836cdb`.
