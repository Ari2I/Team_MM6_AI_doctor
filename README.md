# «Врач»: запуск демонстрации

FastAPI/PostgreSQL принимает XLSX, сопоставляет препараты с МНН по синтетическому
справочнику и проверяет пары «препарат + диагноз». Frontend раздаётся nginx.
Анализ рекомендательный: решение принимает человек. Дозировка, количество
и длительность медицински не оцениваются.

## Запуск с нуля

Нужны Docker с Linux-контейнерами и Compose v2 с поддержкой `--wait`.
Работайте из корня репозитория, ветка `integration/techno-razbor`.

1. Скопируйте `.env.example` в `.env` и заполните пустые поля локально.
   Секреты не коммитить; их значения в документации намеренно отсутствуют.
2. Выполните:

   ```bash
   docker compose up --build -d --wait
   docker compose exec -T api alembic upgrade head
   docker compose exec -T api python -m app.scripts.import_reference data/reference/demo.json --activate
   docker compose ps
   ```

3. Откройте `http://localhost:<WEB_PORT>/`, введите свои `WEB_USER` и `WEB_PASSWORD`
   в диалоге браузера. `/health` открыт без пароля.

Наружу опубликован только web. nginx проксирует `/applications` и `/health`
на `api:8000`; PostgreSQL доступен как `db:5432`. Frontend использует тот же origin:
браузер сам отправляет Basic Auth при загрузке, просмотре карточки и скачивании отчёта.
`.htpasswd` создаётся при каждом старте web из окружения и хранится в контейнере.
После смены учётных данных: `docker compose up -d --force-recreate web`.

Миграции и импорт выполняются явно. Повторный `alembic upgrade head` допустим;
повторный импорт той же версии запрещён. На существующей БД пропустите импорт,
если `demo-api-1` уже импортирована с `--activate`. Том `postgres_data` сохраняет БД.
`docker compose down` останавливает стек без удаления данных.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | БД, пользователь и секрет; обязательны для Compose |
| `POSTGRES_HOST`, `POSTGRES_PORT` | Для локального Python; Compose задаёт `db` и `5432` |
| `WEB_PORT` | Свободный порт хоста; обязателен, значения по умолчанию нет |
| `WEB_USER`, `WEB_PASSWORD` | Обязательные непустые однострочные учётные данные без значений по умолчанию; имя без двоеточия |
| `ENABLE_API_DOCS` | Включает `/docs`, `/redoc`, `/openapi.json` для разработки |
| `ENABLE_APPLICATION_LIST` | Включает `GET /applications` для разработки |
| `MAX_EXCEL_SIZE_BYTES` | Необязательный лимит API; лимит nginx согласуйте отдельно |
| `COMPOSE_PROJECT_NAME` | Необязательное отдельное имя проекта smoke-проверки |

Флаги разработки по умолчанию выключены в Python, включены в `.env.example`
для локальной разработки и принудительно выключены в Compose. В контейнере
для включения нужен явный локальный override `environment` у api.
Не публикуйте вывод `docker compose config` с подставленными секретами.
Пароли со специальными символами в `.env` заключайте в одинарные кавычки.

## Сценарий показа

1. Загрузите `tests/data/sample_ok.xlsx`: покажите МНН, категории, источники,
   версию `demo-api-1` и скачайте XLSX-отчёт.
2. Покажите опечатку и необходимость проверки человеком.
3. Покажите два диагноза: строка без своего диагноза проверяется по обоим,
   результаты пар хранятся отдельно.
4. Загрузите `tests/data/sample_corrupt.xlsx`: ожидается ошибка файла.

Справочник `data/reference/demo.json` демонстрационный, не клиническая истина.
ИИ-модуль здесь не подключён, внешние LLM не вызываются. Демо-файлы будущего
ИИ-адаптера будут добавлены отдельно.

## Smoke в чистой копии

Нужны Bash (на Windows — Git Bash), curl и Docker. Скрипт создаёт отдельный проект,
выполняет миграции, импорт с `--activate`, проверяет защиту, статику, загрузки,
карточки и отчёты через nginx. При выходе удаляет только свой проект и его том.
Имя уже используемого проекта отклоняется. Основной стек не затрагивается.

Экспортируйте свои `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `WEB_USER`,
`WEB_PASSWORD`, `WEB_PORT` (отдельный свободный порт). Скрипт не выполняет
`source .env`: файл Compose не является shell-скриптом. Для секретов используйте
`read -rs WEB_PASSWORD; export WEB_PASSWORD` и аналогично для `POSTGRES_PASSWORD`.

Точные команды после коммита изменений в Git Bash/Linux:

```bash
copy_dir=$(mktemp -d)
git archive HEAD | tar -x -C "$copy_dir"
(
  cd "$copy_dir"
  cp .env.example .env
  export COMPOSE_PROJECT_NAME="vrach-review-$(date +%s)-$$"
  bash scripts/smoke_e2e.sh
)
result=$?
rm -rf -- "$copy_dir"
test "$result" -eq 0
```

Допущение: отдельных фикстур с опечаткой и ровно двумя диагнозами пока нет.
Smoke создаёт временные варианты `sample_ok.xlsx` в памяти: `Нурофен` → `Нурафен`;
для второго сценария оставляет две строки, два учебных диагноза и очищает диагноз
первой строки. Исходные XLSX не изменяет. HTTP-проверки идут из api на
`http://web:80` через nginx; отдельный curl проверяет опубликованный порт с хоста.

## Проверки разработки

Python 3.11, установка: `python -m pip install -e '.[dev]'`.

```bash
pytest -q
ruff check app tests alembic scripts
ruff format --check app tests alembic scripts
docker compose exec -T -e RUN_POSTGRES_TESTS=1 -e ENABLE_APPLICATION_LIST=true api pytest -q
```

Последняя команда — для отдельной тестовой БД: существующие интеграционные тесты
проверяют также разрешённый режим списка. Общий `ruff check .` включает чужой `ai/`,
который в этой задаче не исправляется.

## Сделано после рецензии

- Единый Compose: db, api, web; наружу опубликован только web.
- Basic Auth защищает сайт, статику и API; открыт только `/health`.
- Документация API и список заявок выключены по умолчанию.
- Изолированный smoke с удалением тестового тома.
- Используются существующие синтетический справочник и тестовые XLSX.

## В плане

- Учётные записи и роли с индивидуальными правами.
- Журнал доступа и действий пользователей.
- Сроки хранения и удаление заявок.
- Шифрование хранилища и резервных копий.
- HTTPS для показа по сети: HTTP Basic Auth не шифрует соединение.
- ИИ через backend-адаптер с шаблонным резервом и отдельными демо-файлами.
- Подтверждение аналитиком категорий и правил жёлтого/красного индикатора.

API не хранит отдельного решения секретаря. В демонстрации используйте только
вымышленные данные.
