# LLM/RAG для проверки расходов на материальную помощь

Библиотека помогает сотрудникам отдела материальной помощи, прежде всего
секретарю комиссии по ТЖС, сверять покупки с доступными основаниями и готовить
вопросы для дальнейшего рассмотрения. Она сохраняет происхождение цитат,
неизвестные сведения и причины неполноты. Решение о выплате принимает человек.

Наша часть включает LLM/RAG, ML-2 и импорт XLSX. Общий backend,
frontend, HTTP, БД и развёртывание сюда не входят. Проверка текста и происхождения
цитаты не доказывает клиническую применимость; независимой медицинской оценки
точности на размеченной выборке пока нет.

## Возможности и ограничения

- Публичный `IntegrationRequest` содержит списки диагнозов и покупок и явные
  связи между ними. Нет бизнес-ограничения «только два диагноза»; проверены
  офлайн-сценарии с 1, 2, 10 и 50 диагнозами. Технические бюджеты задаются отдельно.
- Неизвестные МНН, количество, сумма, дозировка и валюта остаются `null`.
  В JSON количество передаётся положительной десятичной строкой, например `"0.5"`.
  В двухлистовой XLSX количество — целое от 1 до 1 000 000, возраст — целое от 0 до 130 лет или пустая ячейка.
- Категория внешнего правила и предложение ML-2 сохраняются раздельно.
  Значения — русские **А/Б/В** или `null`; конфликт не разрешается выбором модели.
- ML-2 сопоставляет МНН по реестру, проверяет роль и дословность цитат. Простое
  сопоставление концентрации выделено отдельно; оно не проверяет схему приёма.
- Каждая явно запрошенная пара имеет результат либо причину, почему она не
  обработана. Фасад подбирает клинические рекомендации (КР) для первых `max_pairs` связей
  в порядке входного списка. Остальные возвращаются в `unprocessed_pairs` с причиной
  `BUDGET_EXHAUSTED`. При загрузке источников учитывается оставшееся время заявки.
- Общая сумма включает каждую уникальную покупку один раз, отдельно по валютам.
  Сумма покупки в JSON и XLSX допускает от 0 до 999 999 999 999,999 включительно
  и до трёх дробных знаков. В JSON это строка с десятичной точкой. Итог по валюте
  может превышать предел одной покупки. Разрезы диагнозов могут пересекаться. Сумма строки не умножается на количество.
- Рекомендации модели содержат проверяемые ссылки на факты/цитаты; при отказе
  остаётся понятный резерв. Свободный текст требует независимой смысловой оценки.
- `human-report.1` — отдельный публичный объект. HTML строится из него без нового
  API-вызова. Полный результат сохраняет техническую детализацию для потребителя.
- Векторный поиск использует GigaChat API либо подготовленный кэш его векторов.
  Локальных моделей и зависимости от их весов нет.

Рабочая поставка полного корпуса ГРЛС/КР пока не объявляется готовой:
распространение существующих копий требует подтверждения прав. В Git включены
инструкции и пустой манифест, а не личная папка автора с данными.
Автономный выбор инструментов агентом не реализован; текущий путь — явный конвейер.

## Установка

Python **3.11+**. Из исходников:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e .
# Для разработки и тестов:
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
```

Runtime-зависимости: Pydantic, python-dotenv, SDK `gigachat==0.2.0`, httpx,
jsonschema и openpyxl. Pytest/build/ruff входят в dev-набор. Для установки
собранного пакета: `python -m pip install path/to/llm_rag-0.2.0-py3-none-any.whl`.
Исходные `examples/request.json` и `examples/corpus.json` устанавливаются в
`share/llm-rag/examples`.
Проверенный набор runtime Windows/Python 3.11 закреплён в
[requirements-py311-win.lock](requirements-py311-win.lock); это не универсальный Linux lock.

## Локальная проверка

Из корня установленного проекта выполните:

```powershell
.venv/Scripts/python.exe check_local.py
```

Команда проверяет все файлы XLSX из `excel_input` рядом с `check_local.py`.
Временные файлы Excel с префиксом `~$` пропускаются. Для проверки одной карточки
можно передать путь к ней первым аргументом. Разбор двухлистной и четырёхлистной книги формирует
один `IntegrationRequest`. Вызов `analyze_request` загружает текущую выгрузку ГРЛС,
выбирает применимую редакцию в рубрикаторе Минздрава, извлекает фрагменты лечения
по МНН и выполняет векторный поиск, классификацию и рекомендации через GigaChat.
Неоднозначная редакция и недостаток условий отражаются в результате пары.

Рабочий вызов проверяет TLS. В локальном файле проверка сертификата выключена
для GigaChat и эмбеддингов. ГРЛС и Минздрав используют HTTPS с проверкой сертификата.
При пакетной проверке отчёты записываются в
`excel_results/check-<дата-время>/<имя XLSX>/`. Для каждой обработанной карточки
сохраняются `result.json` и `report.html`. Пути к HTML выводятся в терминал,
при ошибке чтения имя книги выводится в stderr, обработка продолжается со следующей карточки.
Параметр `--output` задаёт корневую папку результатов, а при проверке одной
карточки — папку для её файлов. Код 0 означает завершённый технический прогон,
1 — получен частичный результат или техническая ошибка, 2 — ошибка входа или запуска.
Окончательная оценка принадлежит специалисту.

## Подключение бэкенда

```python
from llm_rag.integration import analyze_request
from llm_rag.integration_contracts import IntegrationRequest

result = analyze_request(IntegrationRequest.model_validate_json(payload))
```

Настройте `GIGACHAT_CREDENTIALS` или `GIGACHAT_ACCESS_TOKEN`, корпоративный
`GIGACHAT_SCOPE` (B2B или CORP) и при необходимости `GIGACHAT_CA_BUNDLE_FILE`.
При запуске из исходников читается также проектный `.env`; окружение имеет приоритет.
Публичные названия диагнозов берутся из отобранных КР, МНН — из ГРЛС.
В `RAG_NETWORK_TERMS` можно указать путь к JSON со списками публичных терминов
`diagnoses` и `inns`. Для согласованного синонима добавьте запись в необязательный
массив `diagnosis_aliases` с полями `name`, `icd10` и `edition` (ID редакции КР).
Фасад сверяет название с заголовком выбранной КР или синонимом для точного кода
и редакции. При расхождении пара получает причину ручной сверки `DIAGNOSIS_MISMATCH`
до классификации. Категории и цитаты для неё остаются пустыми.
Идентификаторы покупок, суммы и возраст остаются локальными.
Загрузки и векторный кэш хранятся в `RAG_DATA_DIR` (в исходниках по умолчанию
`data/rag`). При наличии проверенной поставки используется её утверждённый корпус.

## Проверки и документация

```powershell
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m ruff check src tests check_local.py
.venv/Scripts/python.exe -m build
.venv/Scripts/python.exe -m llm_rag --export-schemas .local/schemas
```

Обычные тесты не требуют сети, ключа или локальных весов. Живой прогон запускается через `check_local.py`.
История числа пройденных тестов не является оценкой медицинской точности.
