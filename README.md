# Модуль LLM/RAG для проверки расходов

Python-модуль принимает результаты анализа препаратов от предыдущего компонента, ищет основания в предоставленном корпусе и формирует комментарии с цитатами, статусы и резюме заявки. Исходные МНН, категории и результаты проверки дозировки сохраняются.

Поддерживаются генерация через GigaChat, локальные бесплатные эмбеддинги MiniLM и запуск без внешнего API. Для проверки используются учебные заявки без персональных данных. Автономный Excel-сценарий вызывает ML-2 с реальными публичными ГРЛС и КР, затем нашу проверку и оформление отчёта. К общему backend/UI модуль не подключён.

## Установка и первый запуск

Python 3.11 или новее. Команды PowerShell выполняются из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py --output .local/results/demo.json
```

Все внешние зависимости приложения и тестов перечислены в одном `requirements.txt`: `pydantic`, `python-dotenv`, `gigachat`, `httpx`, `torch`, `transformers`, `huggingface-hub`, `pytest`, `jsonschema`, `requests`, `openpyxl`. Команда выше устанавливает библиотеки; проект запускается через `run.py` без отдельной установки. `pyproject.toml` читает зависимости из того же файла, а транзитивные зависимости pip устанавливает автоматически.

По умолчанию запускаются лексический поиск и `DemoProvider`: он извлекает разрешённые утверждения из тестового корпуса и не вызывает LLM. В примере восемь позиций, итог `PARTIAL` и сумма `355.00 RUB`.

## Локальная проверка через меню

```powershell
.\.venv\Scripts\python.exe check_local.py
```

Пункты 1 и 2 запускают демо без API с обычным или векторным поиском. Пункты 3 и 4 вызывают GigaChat с соответствующим способом поиска; выбор этих пунктов разрешает отправку демонстрационного контекста в API. Пункт 5 позволяет выбрать другие JSON-файлы заявки и корпуса. Пункт 6 разрешает или запрещает первоначальное скачивание модели при следующем векторном запуске; по умолчанию скачивание запрещено. Пункт 7 переключает проверку сертификата сервера только для текущей сессии меню. Пункт 0 завершает программу.

Если GigaChat выдаёт `GIGACHAT_TLS_ERROR` и нужно выполнить локальную проверку без установки сертификата, выберите 7, затем 4. Соединение останется зашифрованным, но подлинность сервера проверяться не будет. При новом запуске меню проверка снова включена. Обычный `run.py` всегда использует проверку сертификата. Для работы с проверкой используйте сертификат по [инструкции GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates) и настройку `GIGACHAT_CA_BUNDLE_FILE`.

По умолчанию используются `examples/request.json` и `examples/corpus.json`. Меню показывает статусы, комментарии, цитаты, суммы и путь к полному JSON в `.local/results/`. Каждый запуск сохраняется в отдельный файл. Пути по умолчанию определяются относительно расположения скрипта, поэтому его можно запустить из другой папки. Если у позиций возникли `PROCESSING_ERROR`, меню сообщает о технических ошибках; сохранённый файл сам по себе не подтверждает успешный вызов API.

`check_local.py` и `run.py` вызывают общую функцию `analyze_files()` из `llm_rag.application`, которая использует существующий `Pipeline.run()`. Логика анализа в меню не дублируется.

## Векторный поиск

```powershell
.\.venv\Scripts\python.exe run.py --retrieval vector --output .local/results/vector.json
```

Используется локальная модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`: русский язык, 384 измерения, CPU. На текущем компьютере веса уже есть в стандартном кэше Hugging Face. Если модель отсутствует, первоначальное скачивание разрешается явно:

```powershell
.\.venv\Scripts\python.exe run.py --retrieval vector --download-embeddings --embedding-cache .local/models --output .local/results/vector.json
```

После скачивания используйте ту же `--embedding-cache .local/models` без флага скачивания. Обработка текстов выполняется локально; ключ API для эмбеддингов не нужен. Модель обрабатывает до 128 токенов строки, индекс хранится в памяти.

Источники сначала отбираются по МНН и диагнозу. Затем учитываются явные ссылки и косинусная близость. Все подходящие фрагменты сохраняются для проверки конфликтов. В итоговом `retrieval_info` указаны метод поиска, модель, версия, размерность и отпечаток корпуса.

## GigaChat

Используется [официальный Python SDK `gigachat`](https://developers.sber.ru/docs/ru/gigachain/tools/python/gigachat), версия `0.2.0`. Адаптер вызывает `GigaChat.chat()` с моделью `Chat`; получение, хранение в памяти и обновление токенов выполняет SDK. JSON-ответ дополнительно проверяется кодом проекта по разрешённым утверждениям и цитатам. Сетевой клиент закрывается после обработки заявки; при прямом использовании `GigaChatProvider` используйте `with` или вызовите `close()`.

Схема ответа привязана к идентификатору позиции и разрешённым утверждениям: число элементов ограничено, а текст, цитата и идентификаторы выбираются только в согласованных сочетаниях. Ответ модели всё равно проходит независимую проверку проекта.

Ключ автоматически читается из `.env` в корне проекта или из переменной окружения `GIGACHAT_CREDENTIALS`. В `.env` укажите Authorization Key без префикса `Basic`:

```dotenv
GIGACHAT_CREDENTIALS=ваш_ключ
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2
```

Запустите меню или используйте команду:

```powershell
.\.venv\Scripts\python.exe run.py --provider gigachat --enable-api --retrieval vector --output .local/results/gigachat.json
```

Для проекта организации укажите его scope: `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`. Модель задаётся доступным вашему проекту идентификатором. Вместо Authorization Key можно передать временный `GIGACHAT_ACCESS_TOKEN`; обе переменные одновременно не допускаются. При необходимости собственного доверенного CA bundle задайте `GIGACHAT_CA_BUNDLE_FILE`. Проверка TLS включена по умолчанию; временное отключение предусмотрено пунктом 7 локального меню.

`.env` исключён из Git. Настройки читаются заново при каждом анализе; уже заданные переменные окружения имеют приоритет над файлом. Для другого файла настроек в CLI используйте `--env-file путь`. Секреты не выводятся в меню и не записываются в результат. В CLI API включается флагом `--enable-api`; в меню — выбором пункта GigaChat. Ключ из `.env` не делает обращения к API автоматическими.

Альтернативный провайдер `--provider gateway` отправляет наш внутренний контекст POST-запросом на HTTPS `--endpoint` с `LLM_RAG_API_KEY` в Bearer-заголовке. Он ожидает ответ `{item_id, claims}`, где каждое утверждение содержит `claim_id`, `text`, `fragment_id`, `quote`. Этот протокол не является универсальным API поставщиков.

## Вход и результат

Рабочие примеры: [заявка](examples/request.json) и [корпус](examples/corpus.json). Для собственных файлов:

```powershell
.\.venv\Scripts\python.exe run.py --request examples/request.json --corpus examples/corpus.json --output .local/results/result.json
```

Контракт заявки версии `1.0` включает `request_id`, `diagnosis`, `items`, `is_demo=true` и необязательный словарь `context`. Суммы передаются десятичными строками, категории — кириллическими `А`, `Б`, `В` либо `null`. `dosage_check.status`: `VALID`, `INVALID`, `INSUFFICIENT_DATA`, `NOT_CHECKED`. `upstream_status`: `PROCESSED`, `PARTIAL`, `FAILED`. Окончательные поля ещё предстоит согласовать с предыдущим модулем.

Статусы объяснения: `SUPPORTED`, `INSUFFICIENT_DATA`, `UNCONFIRMED`, `SOURCE_CONFLICT`, `PROCESSING_ERROR`. Результат содержит проверенные утверждения и цитаты, причины, недостающие сведения, ссылки резюме и нерешённые позиции. Полнота: `COMPLETE`, `PARTIAL`, `UNRESOLVED`. При `NOT_CHECKED` подтверждение относится только к категории, а не к дозе или лечению.

Медицинский текст допускается только в точной разрешённой формулировке, размеченной в корпусе. Наличие цитаты само по себе не разрешает другой вывод. Условия не угадываются; категория №2 при конфликте сохраняется. Суммы считаются через `Decimal` по каждой валюте, без повторного умножения на количество. Процент компенсации не рассчитывается. Исходные PDF/Word автоматически в корпус не преобразуются; качество на реальных медицинских данных не подтверждено.

JSON-схемы при необходимости создаются из моделей, а не хранятся в ветке:

```powershell
.\.venv\Scripts\python.exe run.py --export-schemas .local/schemas
```

Код возврата CLI `0` означает, что результат заявки сформирован: отдельные позиции могут требовать проверки или содержать `PROCESSING_ERROR`. Код `2` означает ошибку входа, настройки или файлов.

При известной ошибке GigaChat поле `reasons` содержит безопасный код причины, который меню поясняет по-русски: например, `GIGACHAT_TLS_ERROR`, `GIGACHAT_AUTH_FAILED`, `GIGACHAT_FORBIDDEN` или `GIGACHAT_TIMEOUT`. Произвольные сообщения исключений, заголовки и тела ответов API в результат не включаются.


Кэш и временные файлы тестов размещаются в `.local/`. Реальная модель проверяется отдельно при наличии весов:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
Remove-Item Env:LLM_RAG_TEST_LOCAL_EMBEDDINGS
```

# Пояснения ML-2 к первому демо

## Excel-сценарий для аналитика

1. Положите `.xlsx` по шаблону в `excel_input`.
2. Из корня проекта запустите:

   ```powershell
   .\.venv\Scripts\python.exe run_excel_scenario.py
   ```

3. Откройте `report.html` в новой папке запуска внутри `excel_results`.
   Рядом лежит `result.json`: полный ML-2, независимые снимки, пояснения,
   SHA входного Excel, версия ГРЛС и раздельный расход токенов.

Скрипт вызывает настоящий GigaChat и расходует токены. По прямому выбору пользователя
в этом локальном Excel-сценарии проверка сертификата GigaChat отключена по умолчанию,
включая запуск кнопкой Run в PyCharm. Флаг `--insecure` сохранён для совместимости.
С доверенным сертификатом включите проверку флагом `--verify-ssl`. Публичные источники
используют обычную проверку TLS. Ключи берутся из `.env`/окружения и не входят в отчёт.
При первом запуске скачивается публичный ГРЛС; затем используется сохранённый
снимок из `.local/official-inputs/grls/registry.json`. Для другого явно выбранного
снимка есть `--registry путь.json`; его версия и дата видны в результатах.

Два внешних учебных входа: `01_Подходящие_препараты.xlsx` (астма, сальбутамол и
будесонид) и `02_Препарат_другого_назначения.xlsx` (астма, сальбутамол и метформин).
Независимые ожидания и ссылки на оригиналы КР зафиксированы до первого прогона
в `excel_cases/Ожидания.md`, SHA — в `excel_cases/SHA256.txt`. Скрипт эти ожидания
не читает. Данные заявителя вымышлены, суммы условные. Приложенные файлы не
являются назначением лечения или согласованным эталоном категорий заказчика.

Ограничение текущего реального прогона: ML-2 распознал сальбутамол и будесонид,
но оставил их в NEEDS_REVIEW без категорий, сославшись на отсутствие подтверждённого
золотого стандарта. Метформин для указанной астмы получил NO_EVIDENCE без
автоматической категории В. Полная классификация положительной карточки пока
не достигнута; для её приёмки нужен согласованный эталон категорий команды.

На листе `Заявка` заполняются ID заявки, ID диагноза, диагноз, код МКБ-10
и `Учебная заявка = TRUE`. Возраст необязателен: оставьте пустым или удалите поле,
если данных нет. Возраст и группа не будут угаданы; возрастные цитаты останутся
материалом для ручной проверки с предупреждением о неизвестной применимости.
Необязательное поле `Редакция КР` позволяет
явно выбрать редакцию из каталога. На листе `Покупки` — ID позиции, препарат,
дозировка/форма, количество, полная сумма покупки и валюта. Сумма не умножается
на количество повторно. Используйте значения, а не Excel-формулы. Одна карточка
содержит один диагноз. Поля ФИО/контактов и настоящие персональные заявки текущим
demo-контрактом не поддерживаются и не должны загружаться в этот сценарий.

Весь путь: Excel → ГРЛС → ML-2 с публичными КР → наша проверка сохранённого текста
и цитат → ограниченное оформление → рекомендация сотруднику/резюме/расходы. Код классификатора не меняется,
правила категорий из ответов модели не создаются. Если категория не установлена,
это прямо видно в отчёте; завершение программы не означает успешную медицинскую
классификацию. Отсутствие основания не превращается в В.

Повреждённый Excel не останавливает остальные файлы. Входы не перезаписываются,
файлы `~$...` пропускаются. Код завершения: 0 — файлы обработаны (содержательная
неопределённость допустима), 1 — технические ошибки/API, 2 — ошибки входных файлов.
Пути `--input-dir` и `--output-dir` можно переопределить. Запуск из PyCharm:
`run_excel_scenario.py`, интерпретатор текущего `.venv`; параметры не требуются.

Цитаты не повторяются в общем комментарии: в HTML остаются отдельные блоки
«цитата — ссылка/локатор», сгруппированные по документу и редакции. Сверка текста
с источником не считается медицинским подтверждением применимости цитаты.

Раздел «Что сделать сотруднику» оформляется отдельным запросом GigaChat даже
при NEEDS_REVIEW или NO_EVIDENCE. Модель выбирает порядок и разрешённые формулировки
действий: уточнить сведения, проверить условия источников, передать специалисту,
повторить техническую проверку. Она не назначает лечение, категорию или выплату.
Ответ проверяется на принадлежность парам, допустимость текста и полноту всех
обязательных ограничений. Крупные заявки оформляются пакетами максимум по две
позиции, чтобы ответ помещался в лимит модели. При отказе показаны резервные рекомендации с явной
отметкой; событие не выдаётся за успешную генерацию. JSON содержит `staff_report`,
а `usage.staff_report` отдельно показывает вызовы/ответы/токены оформления отчёта.

Для ручной проверки нового пути без копирования Python-кода в PowerShell:

```powershell
.\.venv\Scripts\python.exe check_explanations.py --offline
.\.venv\Scripts\python.exe check_explanations.py --gigachat
```

Первый режим проверяет библиотеку без API, второй делает два настоящих запроса
на синтетическом примере с настройками из `.env`/окружения и расходует токены.
Вывод содержит результат сравнения с эталоном, число обращений и ответов,
счётчики токенов API и сведения о резервном шаблоне. Ошибка API или отклонённый
ответ означает код выхода 1; наличие готового комментария не выдаётся за успех.
Для GigaChat требуется доверенный сертификат (`GIGACHAT_CA_BUNDLE_FILE`).
Для явно выбранной локальной проверки без сертификата:
`.\.venv\Scripts\python.exe check_explanations.py --gigachat --insecure`.
Флаг действует только на этот запуск; по умолчанию сертификат проверяется.
Русский текст хранится в UTF-8-файле, его не нужно передавать через PowerShell stdin.
Тесты запускаются и из корня, и из `tests`; из `tests` команда:
`..\.venv\Scripts\python.exe -m pytest -q`.

Новый библиотечный путь `explanation.1` сохраняет исходную категорию ML-2,
проверяет цитаты по независимо подготовленному снимку и формирует резюме.
`Pipeline.run()` и контракт `AnalysisRequest` версии `1.0` работают как прежде.
К backend, UI и БД общего приложения новый путь не подключён; отдельный
`run_excel_scenario.py` читает учебные Excel и формирует локальные HTML/JSON-отчёты.

Программный вызов из корня проекта с `src` в `PYTHONPATH`:

```python
import json
from pathlib import Path
from llm_rag.corpus import Corpus
from llm_rag.evidence_snapshot import EvidenceSnapshot
from llm_rag.explanation import explain_pairs
from llm_rag.explanation_contracts import ExplanationInput, PurchaseAmount
from llm_rag.explanation_summary import summarize_explanations

example = json.loads(Path("examples/ml2_explanation.json").read_text(encoding="utf-8"))
inputs = [ExplanationInput.model_validate(v) for v in example["inputs"]]
snapshot = EvidenceSnapshot.model_validate(example["snapshot"])
corpus = Corpus.model_validate(example["approved_corpus"])
pairs = explain_pairs(inputs, snapshot, approved_corpus=corpus)
result = summarize_explanations(pairs, purchases=[
    PurchaseAmount.model_validate(v) for v in example["purchases"]
])
print(result.model_dump_json(indent=2))
```

Если есть `ML2Batch`, вход готовится через
`prepare_explanation_inputs(batch.request, diagnosis_id="d1", ml2_details=batch.details())`.
`diagnosis_id` задаёт вызывающая сторона. Строки сопоставляются по явным ID;
чужие/повторные ID и несовпадающие диагнозы отклоняются. Стоимость пояснению пары
не нужна; адаптер старого `AnalysisRequest` получает его обязательные денежные поля.
`PurchaseAmount.amount` — сумма всей покупки, `None` обозначает неизвестную сумму.
Покупка учитывается один раз по `(request_id, item_id)`, отдельно по валютам.
Денежные разрезы диагнозов и категорий пересекаются и не складываются.

Снимок предоставляет интегратор: текст, МНН/диагноз, условия, источник/фрагмент,
редакция, URL оригинала и копии, локатор и время получения с часовым поясом.
Библиотека не скачивает КР и не удостоверяет подлинность предоставленного снимка.
Пустой URL в ответе ML-2 для согласованного правила разрешается из снимка только
после совпадения фрагмента, версии, цитаты и причины с отдельным `Corpus`.
Незаполненные метаданные обычной цитаты не подтверждают её происхождение.
Свободное условие ML-2 считается неизвестным, кроме дословного совпадения
с уже известным диагнозом. Проверяются также явное условие `ключ=значение`
и структурированные `required_context` снимка/корпуса.

`VERIFIED` означает проверку извлечения в указанном объёме. Только
`classification_basis=APPROVED_RULE` означает найденное применимое согласованное
утверждение; `rule_applied` самого ML-2 доказательством не служит. Цитата без
такого правила остаётся материалом для сверки (`ML2_PROPOSAL`). Все результаты
требуют проверки специалистом; решение о выплате и процент не вычисляются.
Дозировка в новом деморежиме не оценивается, её исходный статус сохраняется.

По умолчанию всё работает без API. Для ограниченного оформления передайте
явно настроенный `GigaChatProvider` как `provider` в `explain_pairs` или
`render_explanation`. Модель получает только ключ пары и разрешённые точные
извлечения; суммы, данные заявителя и произвольный `context` не передаются.
Принимается только полный набор дословных утверждений/цитат с тем же ID пары;
модель может менять порядок разрешённых извлечений, а связки и ограничения
формирует код. Ошибка API или проверки
сохраняет результат и шаблон, отмечая причину в `rendering_reasons`.
Живой вызов GigaChat не является обязательной проверкой и запускается отдельно
только на синтетических данных. Пример содержит синтетический корпус,
независимый снимок, вход, денежные данные и ожидаемый JSON-результат.
