# Рабочие правила классификации ML-2

Текущая версия — `ml2-policy.3`, 11 ноября 2026 года. Режим `CLINICAL_RECOMMENDATIONS`:
категории А/Б/В определяются по применимым цитатам КР без обязательного Master List.
Модуль самостоятельно классифицирует по рабочим правилам; изменения критериев
позже вносятся в тот же файл. Решение о компенсации относится к отдельному этапу.

| Файл | Назначение |
|---|---|
| [classification_rules.json](classification_rules.json) | Единый источник определений ролей, соответствия буквам, причин и лексических проверок цитат. Содержит `policy_version`. |
| [classification_policy.md](classification_policy.md) | Общие условия применимости и неопределённости. Маркер `{{assessment_rules}}` заменяется определениями из JSON. |
| [evidence_extraction.md](evidence_extraction.md) | Задача извлечения, JSON-контракт ответа и требования к дословным цитатам. Получает собранную инструкцию через `{{classification_policy}}`. |

## Как работает категория

- А: КР прямо рекомендует средство или его явно указанную группу для лечения
  заявленного заболевания, контроля болезни, обострения или специфического приступа.
- Б: сопутствующая/вспомогательная терапия неспецифических симптомов, защита органов
  или профилактика осложнений. Клиническая роль определяется моделью по контексту.
- В: источник прямо подтверждает тип опционального средства или недоказанную
  эффективность. Витамин с конкретным лечебным показанием сначала оценивается как
  терапия; отсутствие упоминания или противопоказание сами по себе не дают В.

Модель выбирает роль, код проверяет структуру ответа, дословность цитаты и
лексические условия из JSON. Лексическая проверка — эвристика, не независимая
медицинская экспертиза. Результат по КР имеет `status=PROPOSED`,
`rule_applied=false` и объяснение категории по цитате. `PROPOSED` и
`proposed_category` — сохранённые имена действующего контракта RAG, а не
ожидание будущих правил или повторного назначения буквы. Готовая категория
передаётся в `batch.request.items[].category`. Версия правил
находится в `classification.policy_version`, исходная роль модели —
`classification.model_assessment`, результат проверки — в `assessment`.
При нехватке контекста, конфликте, неизвестном МНН, комбинации, отсутствии
фрагментов или ошибке категория может остаться `null`. Это не В.

Переданный `approved_corpus` по-прежнему применяется первым в `ML2Pipeline`.
Если найдено применимое правило, используются его категория и дословная причина,
`rule_applied=true`; модель не вызывается. Конфликт/недостающие условия правила
не обходятся ответом модели. Источники и цитаты не становятся
утверждёнными правилами автоматически.

## Как изменить правила

Для изменения определения роли, её буквы, пояснения или допустимых формулировок
правится `classification_rules.json`. Текст определения одновременно попадёт в
модельную инструкцию, а категория и шаблоны проверки — в Python-валидатор.
Общие условия правятся в `classification_policy.md`. Требования к форме ответа
и цитатам — в `evidence_extraction.md`. При изменении политики нужно увеличить
`policy_version`, перезапустить процесс и проверить ожидаемые ответы.

```powershell
python -m pytest tests/ml2 -q
```

Промпт не является всем алгоритмом: новые поля ответа, новые типы роли, правила
приоритета, источники или новая обработка контекста могут потребовать правок кода
и тестов. Дословность цитат и отдельные статусы неопределённости остаются общими
проверками. При неверном JSON, пустых файлах или неверных маркерах загрузка
завершается явной ошибкой. Файлы включаются в wheel через `MANIFEST.in`.

## Чтение на стороне RAG

```python
from llm_rag.ml2 import load_classification_policy
from llm_rag.ml2.policy import load_classification_rules

instruction = load_classification_policy()  # Общий текст, собранный из MD и JSON.
rules = load_classification_rules()         # Структурированные критерии и версия.
```

Существующий RAG получает категорию через `batch.request` и
полные детали через `batch.details()`. Он отдельно проверяет основания и может
вернуть `UNCONFIRMED`/`INSUFFICIENT_DATA` при сохранённой букве. Код RAG этим
изменением не переписывается. Инструкции не являются доказательствами назначения
и не загружаются как записи `Corpus`/`EvidenceSnapshot`. Решение остаётся за человеком.

## История

`ml2-policy.1` только выносила прежний промпт из Python без изменения текста.
Версия 2 меняет семантику: предварительная А больше не требует утверждённого
правила и описывает роль в КР, а не доказанную принадлежность к золотому стандарту.

Версия 3 называет рабочий режим `CLINICAL_RECOMMENDATIONS` и успешный результат
категорией по КР. Определения и проверки версии 2 сохранены; убрана формулировка
«предварительная категория» и безусловное требование ручной сверки из причин
успешной классификации. Неопределённость при недостатке оснований остаётся.
