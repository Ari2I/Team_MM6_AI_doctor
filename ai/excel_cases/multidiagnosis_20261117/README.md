# Независимые входы с несколькими диагнозами

Технические ожидания заданы 17.11.2026 до реализации нового импортёра
и обращения к модели. `manifest.json` содержит точные строки и ожидаемые
свойства, `SHA256.json` закрепляет байты десяти XLSX в `input/`.
Все данные синтетические. Категории А/Б/В не размечены: экспертная оценка —
внешняя зависимость, автоматические проверки её не заменяют.

Формат будущего автономного импортёра:

- `Заявка`: единственный ID заявки, без специального флага режима.
- `Диагнозы`: ID, название, необязательные МКБ и возраст.
- `Покупки`: уникальный ID и исходные поля покупки; сумма за строку.
- `Связи`: только явно указанные пары ID покупки и диагноза.

Одна покупка может относиться к нескольким диагнозам. В общем итоге её
стоимость учитывается один раз; разрезы диагнозов могут пересекаться.
Разные валюты не складываются. `two.xlsx` содержит два диагноза, две покупки
и три связи; ожидаемый общий итог 300.30 RUB. Количество второй покупки 0.5.

Другие случаи: 1/10/50 диагнозов, неизвестное средство, отсутствие возраста,
несовпадение формы, RUB/USD, неизвестный ID диагноза в связи и повтор ID покупки.
Для `form_mismatch` будущая проверка использует контролируемый реестр только
с формой 50 мг против входа 100 мг; это условие теста, не утверждение о ГРЛС.

Карточку можно передать в `python check_local.py путь/к/файлу.xlsx`. Запись runtime_compatibility в манифесте описывает момент
создания входов до импортёра и сохранена как история. `ten` и `fifty`
предназначены для офлайн-проверки структуры и бюджетов, а не классификации
вымышленных диагнозов.

Из корня репозитория:

```powershell
.venv/Scripts/python.exe -m pytest tests/test_multidiagnosis_fixtures.py -q
.venv/Scripts/python.exe -m pytest tests/test_integration_excel.py -q
```

Проверяются SHA, все строки/типы, связи, суммы по валютам и сохранность десяти
прежних [независимых карточек](../review_20261112/README.md).
Отдельно проверяется Excel → офлайн-фасад → единые JSON/HTML. Это не медицинская
приёмка и не живой сценарий GigaChat. Основная документация:
[README](../../README.md). Новые случаи добавлять отдельными файлами с
ожиданиями до прогона; существующие не менять под результат модели.
