# Фасад и результат integration-result.1

```python
from llm_rag.integration import analyze_request

result = analyze_request(request)
```

Результат содержит исходный `request`, `pairs`, `unprocessed_pairs`,
`completeness`, `manifest`, `evidence_snapshot`, `costs`, `usage`, `human_report`.
Список результатов вместе с необработанными парами точно покрывает входные
связи без повторов. COMPLETE означает, что обработана каждая пара; отдельные
пары могут содержать техническую ошибку или недостаток оснований.

Для каждой пары отдельно сохраняются upstream_rule_category и proposed_category
в `decision`, основание их происхождения, requires_review=true, версия политики,
evidence_status, машинные reasons, условия, точные citations и пояснение.
Разные категории дают CONFLICT без выбора победителя. Только русские А/Б/В/null.
Предварительное предложение ML-2 не становится утверждённым правилом комиссии.

Концентрация сопоставляется отдельно с MATCH/MISMATCH/UNKNOWN и причиной.
Поддержаны простые единицы массы и концентрации; комбинации/неизвестные
преобразования не угадываются. Совпадение концентрации не подтверждает
лекарственную форму целиком, схему приёма или клиническую применимость.

Общий денежный итог — сумма уникальных покупок отдельно по валютам.
Покупки с неизвестной суммой/валютой перечислены отдельно. Количество не
умножается на сумму: сумма входа относится ко всей строке покупки.
При восстановлении результата из JSON подменённые итоги отклоняются.

Версии реестра, клинического снимка, корпуса и фактически загруженной политики
сохраняются независимо с SHA256. Политика включает правила и системную инструкцию;
поздняя правка файла не выдаётся за уже загруженную версию процесса.
Закреплённые во входе неизвестные версии не используются: все пары помечаются
VERSION_MISMATCH. Сохранённый клинический снимок сверяется по версии/SHA и
цитатам при валидации результата. Цитаты из КР без согласованного правила
сохраняются с отметкой о необходимости сверить клиническую применимость.
Если документ указывает `required_context.age_group`, известный возраст
используется для локального отбора. При неизвестном возрасте сохраняется
запрос на уточнение группы. Политика комиссии остаётся внешним решением.

`max_pairs`, `max_calls`, `max_tokens`, `max_context_bytes` и `deadline_seconds`
задают кооперативный бюджет. Фасад выбирает первые `max_pairs` связей в порядке
`links` до подбора КР. Остальные связи попадают в `unprocessed_pairs` с причиной
`BUDGET_EXHAUSTED`. При нулевом лимите загрузка источников пропускается.
Запросы к ГРЛС и рубрикатору учитывают остаток времени заявки. Нехватка бюджета
возвращает PARTIAL и точный список BUDGET_EXHAUSTED. Библиотека не обещает
жёсткое прерывание Python/SDK; изоляция зависшего процесса — задача потребителя.
Созданный фабрикой клиент принадлежит одной заявке и закрывается. Фабрика не
должна возвращать общий mutable-клиент для параллельных заявок. Ошибка cleanup
сохраняет результат и lifecycle_status=CLOSE_FAILED. Если не хватает бюджета
после классификации, категория/цитаты остаются, рекомендации переходят в резерв,
а полнота становится PARTIAL. CONTEXT_LIMIT отмечает пару без вызова модели.
usage.tokens с UPPER_BOUND — верхняя оценка бюджета, не фактическое списание.
Повтор одинаковой проверки внутри заявки использует сохранённый ответ только
при совпадении разрешённого пакета, локальных условий и версии ресурсов;
`usage.cache_hits` отражает такие повторы. Исходные ID пар сохраняются.
`DIAGNOSIS_MISMATCH` означает, что название диагноза не совпало с заголовком КР
или согласованным синонимом для кода МКБ-10 и редакции. У такой пары
`evidence_status=SOURCE_CONFLICT`, обе категории пусты, цитаты отсутствуют.
`NEEDS_REVIEW` требует сверки применимости КР или результата классификации.
`MODEL_DISABLED` используется при отключённой модели.

`retrieval=vector` и embedding_factory подключают GigaChatEmbedder к реальным
парам ML-2/Excel. Переданные в фабрику budget hooks охватывают metadata и
embeddings; request_limits ограничивает timeout. Векторы ранжируют только
заранее отфильтрованные документы и не скрывают другие редакции/противоречия.
retrieval_info хранит модель/редакцию/размерность и SHA корпуса. Без провайдера
vector не подменяется молча лексическим режимом.

Для интерфейса отдаётся только `result.human_report`. Структура human-report.1
сохранена, одна строка — одна явно заданная пара. Журнал/внутренние ссылки
не добавляются. HTML строится из сохранённого объекта без вызова модели.

См. [вход](integration-input.md), [фикстуры](../excel_cases/multidiagnosis_20261117/README.md)
и [главный README](../README.md). Это библиотечный контракт; HTTP/БД/UI здесь нет.
