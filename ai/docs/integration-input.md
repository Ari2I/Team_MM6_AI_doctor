# Вход библиотеки integration-request.1

Реализована валидация `llm_rag.integration_contracts.IntegrationRequest`.
Фасад `llm_rag.integration.analyze_request` принимает одну валидированную заявку. Импорт XLSX выполняет `read_integration_card`.

Вход содержит `schema_version`, `request_id`, непустые списки `diagnoses`,
`purchases`, `links` и необязательный объект `versions`.
ID диагнозов и покупок уникальны в своей группе в пределах заявки.
Каждая связь явно указывает `item_id` и `diagnosis_id`; неизвестные и
повторные пары отклоняются. Одинаковые названия с разными ID не объединяются.
Непривязанная покупка сохраняется во входе, но не создаёт пар автоматически.

Диагноз: `diagnosis_id`, `name`, необязательный `icd10`, локальные
`conditions` с `age_years` и `pregnant`. Неизвестное условие равно `null`.
Возраст — неотрицательная десятичная строка. Отправка условий провайдеру
этим контрактом не разрешается; сетевой allowlist относится к пункту 11.4.

Покупка: `item_id`, `name`, необязательные `inn`, `dosage`, `quantity`,
`amount`, `currency`. Пропуски сохраняются как `null`; нет подстановки
0, 1 или RUB. Количество положительное, сумма неотрицательная.
Количество и сумма в JSON — десятичные строки, например `"0.5"`, `"100.10"`;
в Python также принимается `Decimal`. Float, bool, NaN/Infinity отклоняются.
Для суммы одной покупки допустим диапазон от 0 до 999999999999.999 включительно.
В JSON используйте обычную десятичную запись без экспоненты, до 12 цифр перед
точкой и до 3 после неё. Превышение точности вызывает ошибку без округления.
Эти же пределы действуют при чтении обеих раскладок XLSX. Для точного ввода
можно указать сумму текстом. Итог по валюте может превышать предел одной покупки.
Валюта — три заглавные латинские буквы либо `null`; конвертации нет.

В двухлистовой карточке XLSX («Заявка» и «Покупки») возраст можно оставить пустым
или указать целым числом от 0 до 130 лет. Количество обязательно и должно быть
целым числом от 1 до 1 000 000 включительно. При импорте дробные значения
отклоняются с учётом исходной точности ячейки.

`versions` содержит независимые необязательные ссылки `registry`, `clinical`,
`corpus`, `policy`. Фасад сверяет закреплённые версии с переданными ресурсами,
а в полном результате сохраняет SHA. Одной валидации входа для этой проверки
недостаточно. Отсутствующая закреплённая версия даёт VERSION_MISMATCH.
Схема запрещает неизвестные поля во всех объектах, в том числе `is_demo`
и произвольный `context`. Специального режима для синтетических входов нет.

Пример валидации из корня проекта после установки зависимостей:

```python
from llm_rag.integration_contracts import IntegrationRequest

request = IntegrationRequest.model_validate({
    "schema_version": "integration-request.1",
    "request_id": "R1",
    "diagnoses": [{"diagnosis_id": "D1", "name": "Бронхиальная астма"}],
    "purchases": [{"item_id": "P1", "name": "Сальбутамол", "quantity": "0.5"}],
    "links": [{"item_id": "P1", "diagnosis_id": "D1"}],
})
assert request.purchases[0].amount is None
assert IntegrationRequest.model_validate_json(request.model_dump_json()) == request
```
