# Сборка защиты: только фасад AI

После исправления подбора категорий и добавления AI-книг используйте актуальную
[контейнерную приёмку](category-fix-acceptance.md). Новые миграции обязательны;
исходники AI этой сборки содержат локальные исправления поверх 8836cdb.

По согласованному решению тимлида в этой сборке backend-справочник не участвует
в анализе. Он остаётся в БД и доступен прежним режимам; удаление отложено.
API, схема БД, frontend и AI-библиотека не меняются.

`docker-compose.defense.yml` включает `AI_MODE=network` и
`AI_USE_BACKEND_REFERENCE=false`. Без этого override сохранён прежний режим с
backend-правилами. Настройка `false` допустима только в `network`: она не включает
сеть в `template/offline`. Один изолированный worker вызывает публичный
`analyze_request()` один раз на всю разобранную заявку. Прежний попарный адаптер
и поиск по backend-справочнику пропускаются, в том числе при сохранении отчёта.
Таймауты, принудительное завершение worker и обязательная проверка TLS сохранены.

## Что показывается

- В `item_checks` попадает категория из `decision` фасада. При `CONFLICT` категория
  пустая; обе исходные категории остаются в полном `IntegrationResult` и AI-отчёте.
- Если фасад не определил категорию, пара не обработана или worker не вернул
  валидный результат, категория равна `null`; в Excel ячейка пустая. Всегда
  `needs_review=true`. Учебная категория не подставляется.
- Ошибка генерации пояснения не отменяет уже возвращённую классификацию фасада;
  её причина показывается рядом с предварительной категорией.
- МНН берётся из результата фасада; старые SQL-МНН очищаются перед новым вызовом.
  Числовой `match_confidence` не выдумывается.
- Источник — название, версия, раздел и URL первой проверенной цитаты. В поле
  версии сохраняются помеченные версии ресурсов из `manifest`, начиная с
  `grls:`, если реестр действительно присутствует. Без цитаты это явно указано;
  отсутствие источника не заменяется сведениями из demo-api-2.
- В существующих подробностях карточки и Excel показываются пояснение,
  первые вывод/неопределённость/вопрос из `human_report` и первая дословная цитата.
  Полный отчёт со всеми цитатами и основаниями сохранён отдельно. Сводка включает
  тексты `human_report` и прежний детерминированный расчёт долей/светофора.
- Полный валидированный `IntegrationResult` сохраняется по ID заявки атомарно
  с карточкой. В `checks[].backend_rule` нет SQL-категории, есть явная отметка,
  что backend-проверка отключена. `GET /applications/{id}/ai-report` сохраняет
  прежний контракт обёртки `ai-report.1`. Новый frontend-экран можно подключить позже.
- GET карточки, AI-отчёта и Excel читает сохранённые данные без вызовов фасада.
  Ранее сохранённые заявки автоматически не пересчитываются.

## Включение в прежнем терминале

Предполагается, что `dc_acceptance` уже выбирает проверенные Compose-файлы,
CA, постоянный том и тот же проект/порт. Ключ и Basic Auth уже заданы пользователем;
их значения не печатать. Никакого импорта demo-справочника для нового пути не нужно.

```bash
dc_defense() {
  dc_acceptance -f docker-compose.defense.yml "$@"
}

export AI_BACKEND_REVISION="$(git rev-parse HEAD)"
export AI_LIBRARY_REVISION="$(git log -1 --format=%H -- ai/src/llm_rag)"
export GIGACHAT_SCOPE=GIGACHAT_API_B2B

git diff --quiet HEAD -- ai/src/llm_rag
dc_defense build api web
dc_defense run --rm --no-deps api alembic upgrade head
dc_defense up -d --no-build --force-recreate --wait --wait-timeout 180 api web
dc_defense exec -T api alembic check
dc_defense exec -T api python scripts/check_network_build.py --check-probe
```

Если ранее был подключён `docker-compose.no-egress.yml`, не включать его в эту
обёртку. Последующая реальная загрузка требует внешней сети. Не удалять тома.
Используется прежний `RAG_ACCEPTANCE_TERMS`, если он был явно выбран для
проверенного контрольного примера. Контрольный файл содержит соответствие МКБ/КР;
это не полный рабочий справочник всех диагнозов.

## Контейнерная регрессия без модельных вызовов

```bash
dc_defense cp sample_api_response.json api:/app/sample_api_response.json
dc_defense exec -T api python - <<'PY'
import os
import pytest

for key in ('DOCS_ENABLED', 'LIST_ENDPOINT_ENABLED', 'ENABLE_API_DOCS'):
    os.environ.pop(key, None)
for key in ('GIGACHAT_CREDENTIALS', 'GIGACHAT_ACCESS_TOKEN'):
    os.environ.pop(key, None)
os.environ['RUN_POSTGRES_TESTS'] = '1'
os.environ['ENABLE_APPLICATION_LIST'] = 'true'
os.environ['RAG_TEST_DATA_DIR'] = '/run/rag'
raise SystemExit(pytest.main(['-q', '-r', 'fEs', '--tb=no']))
PY
dc_defense exec -T api ruff check app tests alembic scripts
dc_defense exec -T api ruff format --check app tests alembic scripts
```

Удаление ключа выше действует только на процесс тестов; работающий API его
сохраняет. `tests/conftest.py` сбрасывает флаг выбора справочника вместе с остальными
AI-настройками. Каждый тест явно выбирает свой режим. Новые PostgreSQL-тесты
активируют demo-api-2 внутри откатываемой транзакции и доказывают его неучастие:
POST → карточка → JSONB → повторные GET → Excel, отсутствие категорий при сбое,
очистка старого результата и атомарность. Worker подменён, попытки сети запрещены.

## Приёмка через веб

1. Открыть прежний сайт на порте `18081`, войти с Basic Auth. Загрузить один
   ранее проверенный положительный синтетический XLSX с полным МНН, подходящим
   МКБ/диагнозом и той же возрастной группой. Это новая заявка и один вызов фасада;
   он может выполнять несколько запросов GigaChat/Embeddings внутри обработки.
2. Открыть «Подробнее»: источник/версия должны относиться к AI-результату,
   а не demo-api-2; при наличии оснований видны точная цитата и ссылка на Минздрав.
   Категория может оставаться пустой при неизвестных условиях применимости.
3. Скачать Excel: категория, причина, источник, версия и комментарий совпадают
   с карточкой. Неизвестная категория — пустая ячейка и «Требует проверки».
4. Проверить сохранённый `/applications/{id}/ai-report`: `MODEL`, снимок оснований,
   версии ресурсов, правильный SHA; `checks[].backend_rule.category=null` и
   отметка отключения. `COMPLETE`/HTTP 200 сами по себе не подтверждают вызовы модели.
   Для строгой проверки GigaChat/Embeddings использовать [сетевой контроль](network-controls.md)
   с **новыми** каталогами `acceptance-controls-defense` и
   `.local/network-controls-defense`, новым baseline и `dc_defense` вместо
   `dc_acceptance`. `AI_MODE=template` из того сценария этот override намеренно
   перекрывает; подготовка ресурсов сама модель не вызывает. После подготовки
   выбрать новый `RAG_ACCEPTANCE_TERMS` и пересоздать API перед загрузкой.
5. Для отрицательного случая категория/цитаты должны оставаться пустыми;
   ни сбой, ни отсутствие оснований не возвращают учебную категорию.
6. Перечитать карточку/AI-отчёт/Excel после отключения внешней сети по прежней
   процедуре. Это проверяет чтение сохранённого результата без новых запросов.

Не запускать `capture_golden.py` или `compare_golden.py` против network-сборки:
они делают четыре новых POST и сравнивают прежнее поведение SQL-режима. Старые
golden не перезаписывать. Для них и прежнего smoke использовать сборку template.

Изолированный smoke прежнего режима (порт `18083` должен быть свободен):

```bash
COMPOSE_PROJECT_NAME="vrach-defense-smoke-$(date +%Y%m%d-%H%M%S)" \
  WEB_PORT=18083 RUN_POSTGRES_TESTS=0 bash scripts/smoke_e2e.sh
```

## Возврат к прежней сборке

```bash
export AI_MODE=template
dc_acceptance up -d --no-build --force-recreate --wait --wait-timeout 180 api web
```

Не добавлять `docker-compose.defense.yml` в эту команду. Это переключение
настройки; существующие карточки не изменяются. Сеть новых загрузок выключена.

Контракт библиотеки: [docs/integration.md](../ai/docs/integration.md).
