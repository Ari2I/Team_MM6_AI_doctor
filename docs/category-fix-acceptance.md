# Исправление подбора категорий: результат и контейнерная приёмка

Рабочая ветка — `demo/28-11-ai`. Все изменения локальные. Фактический worker до правок
подтверждён пользователем: `/app/app/services/integration_worker.py` вызывает
`/app/ai/src/llm_rag/integration.py`, SDK `0.2.0`, TLS включён, сеть при проверке
исходников не открывается. Исходная поставка AI — `8836cdb`; новые исправления
находятся в подкаталоге `ai/` этой интеграционной ветки, в upstream они не опубликованы.

Основные коммиты: `341de67` (проверка worker), `10b43bd` и `9513aef` (подбор/пакеты),
`95c2cf4` (общий XLSX-парсер), `1b820b0` (веб-вход/хранение), `1aa50d3` и `19d7930`
(история/параллельные запуски), `b4082b0` (итоговая AI-ревизия), `6b0277d` (подсказка UI).
Для окончательной ревизии сборки перед командами ниже используется текущий `HEAD`.

Дополнение `8c747d7`: исправлен ложный `CONTEXT_LIMIT` на подготовке источников.
Окно соседнего текста 900 символов больше не ограничивает длину целого предложения:
допустимая цитата до 3000 символов сохраняется вместе с условиями. Слишком длинная
рекомендация чужой группы не блокирует МНН без подтверждённой связи; релевантное
предложение сверх предела по-прежнему приводит к техническому отказу, а не обрезке.
В плотном тексте каждое окно укладывается в 20 вариантов цитат, чтобы поздний тезис
не исчезал за внутренним пределом вариантов.

Лимит Embeddings 4000 байт не увеличен. Фрагменты сверх него сохраняются целиком
для пакетной классификации и сверки противоречий; ранжируются существующими правилами
подбора без вектора. Диагностика отдельно считает `embedding_ranked_count` и
`embedding_unranked_count`. Если векторный поиск фактически не выполнялся,
`retrieval_info.method` остаётся `lexical`. Это не считается подтверждением сетевой
приёмки Embeddings. Категории, TLS, таймауты и бюджеты не изменялись.

Проверки дополнения: 656 AI-тестов под запретом сети; 576 backend-тестов и 104 пропуска;
ruff успешно. Отдельный запуск с локальным рабочим RAG-кэшем дал 2 отказа по сроку
его актуальности ещё до подбора (CLINICAL_CACHE_INVALID); даты и кэш не менялись.
Контейнерные проверки и успешный повтор живой книги после дополнения ещё ожидаются.

Локальная проверка основного этапа: backend **575 passed, 104 skipped** (101 PostgreSQL,
3 рабочего RAG-кэша); AI **647 passed** под запретом сетевых сокетов/DNS; frontend
**30 passed**, TypeScript и production-build успешно, `.env` при Vite-build не читался.
Ruff по backend и изменённым AI-файлам прошёл. Граф миграций имеет одну вершину
`e1f2a3b4c5d6`; выполнение SQL новых миграций ждёт контейнерной проверки.

## Что изменено

- `ml2/official.py` читает разделы выбранной КР, включая определения и таблицы.
  Поиск кандидатов отделён от упаковки: `ml2/evidence_selection.py`,
  `ml2/clinicalrecs.py`, `runtime.py`. Полные связанные основания ранжируются до квоты.
- Прямая рекомендация и групповая цепочка проверяются существующей политикой
  `ml2-policy.4`, включая принадлежность по АТХ в том же источнике/редакции.
  Семантика букв и файл правил не изменялись. Дефисы нормализуются для поиска;
  цитируется исходный текст сохранённого фрагмента.
- `ml2/evidence_evaluation.py` оценивает ограниченные пакеты через прежний
  классификатор. Связанный набор не разрезается. Отрицания, несовместимые категории,
  неполный контекст, сбой провайдера и незавершённый поиск не превращаются в букву.
  Допускается одна повторная оценка пропуска модели с фактическими условиями.
- `classification-diagnostics.1` сохраняет исходный/итоговый тезис, причину,
  missing_context, этап, ссылки на фрагменты и счётчики. Старые результаты без
  диагностики остаются читаемыми. Это поле полного IntegrationResult в БД;
  HTTP-контракт карточки/панели `ai-report.1` не расширялся.
- CLI и веб используют общий `integration_excel`-парсер. Поддерживаются прежние
  две/четыре страницы; в четырёхлистной книге к исходным столбцам «Диагнозы» можно
  добавить «Возрастная группа» (`adult`/`child`) и «Редакция КР». В двухлистной книге
  это поля листа «Заявка». Отсутствующий возраст не подставляется.
- Миграция `d0e1f2a3b4c5` добавляет `applications.integration_input` (канонический
  `integration-request.1` с локальными UUID, возрастом, редакциями и явными связями).
  Сумма хранится без округления до двух знаков; прежние суммы в карточке сохраняют
  два знака. Прежний плоский Excel работает по прежним правилам связей.
- Миграция `e1f2a3b4c5d6` добавляет историю AI-отчётов и идентификатор запуска.
  История и текущая проекция сохраняются в общей транзакции. Идентичный снимок
  не дублируется; сохранение с устаревшим идентификатором запуска отклоняется.
  Массовый пересчёт и изменение существующих ручных решений не выполняются.
- В frontend изменена только подсказка UploadForm: прежний текст «читается первый
  лист» больше не описывает все поддерживаемые форматы. Остальной UI и API не менялись.

TLS остаётся включённым в backend, Embeddings и `check_local.py`. Старые три проверки
CLI, требовавшие `verify_ssl_certs=False`, заменены проверками `True` по требованию
безопасности. Иные прежние тесты не удалялись и не ослаблялись. Dockerfile и зависимости
не менялись; тяжёлые пакеты не добавлялись.

## Воспроизведение и граница проверки

До исправления получены шесть падающих регрессий исходного подбора: потеря группы/АТХ,
позднего положительного/отрицательного основания, зависимость от порядка, дефисы,
определения вне раздела лечения. Отдельно воспроизведены отказы фасада при числе
кандидатов >20, отсутствие пакетной сверки/повтора. После исправления эти тесты зелёные.

| Технический контроль | До | После локально | Основание |
|---|---|---|---|
| Синтетическая групповая цепочка сальбутамола | Рекомендация потеряна | А | Групповая рекомендация + отдельная дословная связь МНН/АТХ |
| Связь удалена / другой МНН / другая редакция | — | Пусто | Отрицательные контроли того же валидатора |
| Поздняя рекомендация будесонида после 9 упоминаний | Потеряна квотой | Доставлена классификатору вместе с возрастным условием | Синтетический полный абзац, без вырезания условия |
| Пакеты с отрицанием / А и Б | Нет итоговой пакетной сверки | Пусто, конфликт | Проверенные цитаты сохраняются |
| Синтетические эталоны А / Б / В | — | А / Б / В | Для В есть собственная цитата по действующей политике |
| Поздний сбой/исчерпание бюджета | Ранний отказ по размеру | Технический отказ, без буквы | Не выдаётся категория по части поиска |

Это техническая разметка, не независимая медицинская экспертная выборка.
Живая учебная книга, исходная запись из диагностики и таблица реальных цитат до/после
ещё требуют проверки пользователем. Их категории не объявлены исправленными по одним unit-тестам.

## 1. Пересборка и миграции

В прежнем терминале с уже настроенными `dc_defense`, CA, B2B-ключом и Basic Auth.
Ни ключи, ни сертификаты повторно передавать/печатать не нужно. Том и кэши сохраняются.

```bash
export AI_BACKEND_REVISION="$(git rev-parse HEAD)"
export AI_LIBRARY_REVISION="$(git log -1 --format=%H -- ai/src/llm_rag)"
dc_defense build api web
dc_defense run --rm --no-deps api alembic upgrade head
dc_defense up -d --no-build --force-recreate --wait --wait-timeout 180 api web
dc_defense exec -T api alembic check
dc_defense exec -T api python scripts/check_network_build.py --check-probe
dc_defense exec -T api python scripts/check_ai_worker_source.py
```

Для сверки хэшей с хостом: `.venv/bin/python scripts/check_ai_worker_source.py`.
В `files` значения должны совпадать; абсолютные пути на хосте и в контейнере различаются.
Для сборки защиты импорт backend demo-справочника не требуется.

## 3. Живая учебная книга через веб

Сначала веб, затем CLI: иначе CLI заранее наполнит кэш эмбеддингов этой же книги.
Перед первой загрузкой зафиксировать только хэши существующих векторов:

```bash
dc_defense exec -T api python -m scripts.verify_category_acceptance \
  --baseline-only --baseline /var/lib/vrach/rag/category-check-1/before.json
shasum -a 256 'ai/excel_input/01_Подходящие_препараты.xlsx'
```

Ожидаемый SHA книги: `e287ce837e92351e302709b02e4cbac0db5b14d503c7fe5288130939aae8843d`.
Открыть прежний сайт на `18081` и загрузить эту книгу. Дополнительные диагнозы
оставить пустыми, возрастную группу — «Не указана»: точный возраст/редакция берутся
из книги. Записать ID новой заявки из адреса страницы. Не пересчитывать старую запись.

Подставить **новый** ID вместо `NEW_APPLICATION_UUID`:

```bash
dc_defense exec -T api python -m scripts.verify_category_acceptance \
  --application-id NEW_APPLICATION_UUID \
  --baseline /var/lib/vrach/rag/category-check-1/before.json \
  --output /var/lib/vrach/rag/category-check-1/result.json --require-categories
mkdir -p .local
dc_defense cp api:/var/lib/vrach/rag/category-check-1 .local/category-check-1
```

Скрипт не вызывает AI: сверяет сохранённый полный IntegrationResult, actual policy,
SHA сборки, MODEL, новые относящиеся к заявке векторы и соответствие `item_checks`.
Групповая цитата может не содержать МНН: проверенная связь хранится отдельной цитатой.
В консоли только счётчики, буквы и фиксированные коды. Полный результат пишется
в приватный JSON (0600). Секреты, сырые промпты и окружение туда не добавляются.
Если все векторы уже были в кэше до baseline, свежий вызов Embeddings этим прогоном
не подтверждён. Кэш ради зелёной проверки не удалять.

В карточке, «Разборе ИИ» и скачанном Excel сверить **каждую** пару: букву или
обоснованное пустое поле, точную редакцию и достаточную дословную цитату.
Особо две пары из задания: сальбутамол и будесонид, КР 359_3.
Счётчики не заменяют сверку правильности буквы с владельцем политики.

## 4. Повторное открытие без внешней сети и CLI

```bash
dc_defense -f docker-compose.no-egress.yml up -d --no-build --force-recreate \
  --wait --wait-timeout 180 api web
dc_defense -f docker-compose.no-egress.yml exec -T api \
  python scripts/verify_network_acceptance.py --check-egress-blocked
```

Повторно открыть сохранённую карточку/панель и скачать Excel. Нового анализа быть
не должно. После этого вернуть обычную сеть и отдельно проверить тот же общий CLI:

```bash
dc_defense up -d --no-build --force-recreate --wait --wait-timeout 180 api web
dc_defense cp ai/check_local.py api:/app/ai/check_local.py
dc_defense cp 'ai/excel_input/01_Подходящие_препараты.xlsx' api:/tmp/category-control.xlsx
dc_defense exec -T api python ai/check_local.py /tmp/category-control.xlsx \
  --output /var/lib/vrach/rag/category-check-1/cli
```

CLI после веба вправе использовать уже заполненный кэш; это нужно отметить в отчёте.
Его библиотечный бюджет по умолчанию 300 с отличается от бюджета backend-worker
(обычно 90 с). Таймауты не увеличивались. Успешный CLI сам по себе не доказывает
успех веб-загрузки. Новые прогоны проводить с новым именем `category-check-2` и т. д.,
а не перезаписывать прошлые результаты.

## 5. Приватное сравнение сохранённых версий

`scripts/export_category_comparison.py` читает БД в транзакции READ ONLY, не запускает
worker и ничего не пересчитывает. Аргументы `--before`/`--after` — ID заявки либо UUID
строки `application_ai_history`. Сравнение одинаковых фактов отделено от изменения
возраста/редакции; отсутствующая старая пара не выдаётся за исправленную.

```bash
dc_defense exec -T api python -m scripts.export_category_comparison \
  --before BEFORE_UUID --after AFTER_UUID \
  --output /var/lib/vrach/rag/category-check-1/comparison.json
dc_defense cp api:/var/lib/vrach/rag/category-check-1/comparison.json \
  .local/category-check-1/comparison.json
```

Файл содержит МНН, диагноз/МКБ/условия/редакцию, категории, причины и дословные цитаты.
Он не содержит торговых названий/дозировок/сумм/исходных ID/имён файлов. Промпты и
ключи не экспортируются. Для коллеги таблицу реальных пар заполняют по этому файлу;
содержимое заявок в терминал и общий лог не выводят.

Перед выпуском остаются пользовательская контейнерная приёмка, клиническая сверка
контрольных букв/цитат, итоговое smoke и обновление резервного видео/скриншотов.
Push, теги и слияние в main — отдельные действия после приёмки.
