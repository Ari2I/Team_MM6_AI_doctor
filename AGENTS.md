\# AGENTS.md



\## Проект

Backend ИИ-ассистента «Врач» для секретаря комиссии по трудным жизненным ситуациям. Система принимает Excel-заявку (торговое наименование, дозировка, количество, сумма, диагноз), сопоставляет препараты с МНН, относит их к категориям А/Б/В, считает доли сумм, формирует цветовой индикатор (зелёный/жёлтый/красный), комментарии и резюме. Результат носит \*\*рекомендательный характер\*\*, решение принимает человек.



Команда: backend (я), frontend, 2 AI/ML (LLM+RAG; МНН и классификация), аналитик. Мой код: приём и валидация Excel, API, БД, оркестрация анализа, закрытый контур.



\## Стек

Python 3.11, FastAPI, Pydantic v2, SQLAlchemy 2.x, Alembic, PostgreSQL, pandas + openpyxl, pytest + httpx, ruff, Docker Compose.



\## Структура

Если структура в репозитории отличается, следуй репозиторию, а не этому списку.



\## Команды

\- Запуск: `docker compose up --build`

\- Тесты: `pytest -q`

\- Линт/формат: `ruff check . --fix \&\& ruff format .`

\- Миграции: `alembic revision --autogenerate -m "msg"`, `alembic upgrade head`



Перед тем как считать задачу выполненной, запусти тесты и ruff.



\## Правила кода

\- Типы везде, Pydantic-схемы на границах API; бизнес-логика в `services/`, а не в роутерах.

\- Чистые функции для расчётов (доли сумм, светофор): без обращения к БД, легко тестируются.

\- Каждый шаг анализа (`normalize\_to\_mnn`, `classify`, `check\_dosage`, `generate\_comment`, `generate\_summary`) отдельная функция с чёткими входом и выходом: модули AI/ML подключаются вместо заглушек без переписывания остального.

\- Пороги, словари синонимов заголовков и правила светофора живут в конфиге, не в коде. Неуточнённое помечай `TODO: уточнить у аналитика`.

\- Сообщения об ошибках для пользователя на русском, без технических деталей. Единый формат: `{code, message, row, column}`.

\- Любое изменение схемы БД только через миграцию Alembic.

\- Пиши тесты вместе с кодом; для парсера и валидации используй файлы из `tests/data/`.



\## Персональные данные (закрытый контур)

\- Диагнозы, названия препаратов и содержимое заявок \*\*не логировать\*\* и не выводить в сообщения об ошибках.

\- Никаких внешних облачных API и сторонних сервисов для обработки заявок.

\- Не коммитить реальные заявки и секреты; `.env` в `.gitignore`, примеры в `.env.example`.

\- Тестовые данные только вымышленные.



\## Предметные правила

\- Категории А/Б/В и правила светофора определяет аналитик. Известно: зелёный, если больше 80% суммы приходится на категорию А. Остальное не выдумывай: делай конфигурируемую заглушку и сообщай, что правило нужно уточнить.

\- Расчёты сумм и долей делает код, не LLM.

\- При неопределённости система возвращает «неопределённо», а не придуманное медицинское обоснование.

\- Всегда отдавать дисклеймер о рекомендательном характере анализа.

\- Заявка может иметь несколько диагнозов: хранить в отдельной таблице, у строки препарата диагноз необязателен.
\- Результат анализа строки единый объект: mnn, category, confidence, source, needs_review, review_reason, comment. Правила и ML-модули возвращают один и тот же формат.

\- Индикатор допускает значение undetermined (нужна проверка человеком).

\- Основная логика детерминированная (справочники и правила). LLM подключается только через адаптер LLMProvider, по умолчанию отключён, комментарии строятся из шаблонов.

\- Рекомендация ИИ и решение секретаря хранятся раздельно; система статус заявки не меняет.



\## Как работать

\- Сначала кратко опиши план и затронутые файлы, затем делай небольшими шагами; изменения минимальные и по задаче.

\- Не придумывай форматы данных, которых нет в ТЗ: фиксируй допущение в коде или README и перечисли его в ответе.

\- Контракты на стыках с другими модулями (JSON API для frontend, интерфейсы для AI/ML) не меняй без явной просьбы; если изменение необходимо, предложи и объясни последствия.

\- Не удаляй и не переписывай существующие тесты, чтобы они проходили; исправляй код.

\- Если требование неясно или противоречиво, спроси, а не угадывай.
