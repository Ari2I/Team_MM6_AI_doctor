# Тестовые заявки

Все заявки вымышленные. По согласованию с пользователем выбраны существующие
торговые наименования: «Нурофен», «Но-шпа», «Панадол», «Конкор», «Омез»,
«Супрастин»; диагнозы обозначены как «Учебный диагноз 01»–«Учебный диагноз 03».
Значения дозировок, количеств, сумм и диагнозов — синтетические тестовые данные,
не относятся к реальным людям и не являются медицинскими рекомендациями.
Анализ носит рекомендательный характер. Решение принимает человек.

| Файл | Сценарий |
| --- | --- |
| `sample_ok.xlsx` | 6 строк, ровно пять столбцов из ТЗ, числовые количества и суммы. |
| `sample_missing_column.xlsx` | Те же данные, но полностью удалён столбец «Сумма». |
| `sample_bad_types.xlsx` | В D2 вместо числа текст «не число»; остальные ячейки как в корректной заявке. |
| `sample_empty.xlsx` | Пять заголовков, ни одной строки данных. |
| `sample_messy_headers.xlsx` | Данные как в корректной заявке; регистр, пробелы и переносы строк в заголовках изменены. |
| `sample_corrupt.xlsx` | Обычный текст UTF-8 с расширением `.xlsx`, имитирующий переименованный `.txt`. |

Эти файлы используются тестами парсера `tests/test_excel_parser.py`.
Валидатор пока не реализован. Отсутствующие столбцы и ошибки разбора чисел
фиксируются парсером без проверки бизнес-правил. Коды ошибок API здесь не задаются.

Допущения для тестового набора: один лист «Заявка», заголовки в первой строке,
«Количество» — положительное целое число, «Сумма» — числовое значение строки,
«Дозировка» — текст с единицей измерения. Это соглашения о тестовых данных,
а не новые правила валидации или медицинского анализа.

В репозитории отсутствует ТЗ с примерами препаратов. Пользователь разрешил
подобрать торговые наименования самостоятельно. Файл `sample_ok.xlsx` корректен
по структуре и типам; сопоставление с МНН и медицинские правила не проверяются.

Для повторного создания всех шести файлов из корня проекта:

```sh
python tests/data/generate_samples.py
```

Скрипт использует установленный `openpyxl` и перезаписывает только перечисленные
шесть файлов в своём каталоге. Чтобы изменить тестовые данные, отредактируйте
`SAMPLE_ROWS` в `generate_samples.py` и повторите команду.

Дополнительные примеры парсера используют только вымышленные «Учебные препараты»
и создаются отдельно, без перезаписи исходных шести файлов:

```sh
python tests/data/generate_parser_samples.py
```

| Файл | Сценарий |
| --- | --- |
| `sample_parser_layout.xlsx` | Заголовки в строке 10, ложное совпадение в строке 1, пустые строки, неизвестный столбец, пробельные символы, валюта, отрицательные числа и ноль. |
| `sample_parser_duplicates.xlsx` | Два столбца «Сумма» с разными значениями. |
| `sample_parser_no_headers.xlsx` | Лист с текстом без известных заголовков. |
| `sample_parser_late_header.xlsx` | Заголовки в строке 11 — за пределами поиска. |
| `sample_parser_blank.xlsx` | Полностью пустой первый лист. |
| `sample_parser_no_sheets.xlsx` | XLSX, из описания книги которого удалены листы. |

В дополнительных книгах, кроме примера без листов, есть второй лист с посторонним
текстом: парсер должен читать только первый лист. Количества и суммы здесь могут
быть отрицательными или нулевыми, поскольку проверка бизнес-правил не входит в парсинг.
