# Контрольные карточки демо

Снимки создаются только из четырёх фиксированных синтетических файлов `data/demo/`
через работающий тестовый стек с активным `demo-v2.json`. Реальные заявки сюда
не сохраняются. Каталог не является журналом пользовательских данных.

Из корня проекта:

```bash
.venv/bin/python scripts/capture_golden.py
.venv/bin/python scripts/compare_golden.py
```

Обе команды получают `WEB_URL`, `WEB_USER`, `WEB_PASSWORD` из окружения без чтения
`.env`. Значения не выводятся. Для HTTP допустим только localhost/loopback;
проверка сертификатов HTTPS включена. Redirect отключён.

Capture делает четыре POST и четыре GET сохранённых карточек. Это создаёт четыре
новые заявки в тестовой БД при каждом запуске. Все результаты сначала проверяются
в памяти; если справочник не синтетический или версия отличается от `demo-api-2`,
снимки не создаются. ID, даты и длительности удаляются; все списки сортируются.
Существующие JSON не перезаписываются без явного `--overwrite`.

Compare по умолчанию заново загружает те же файлы и сравнивает результат с этим
каталогом; сохранённые снимки не меняет. Коды выхода: 0 — совпадение, 1 — различия,
2 — ошибка. В консоль выводятся только имена полей, категории, индикаторы и коды
причин из известного enum; остальные значения скрыты. Неизвестные ключи скрыты.

Для сравнения двух локальных наборов без сети:

```bash
.venv/bin/python scripts/compare_golden.py --current-dir /tmp/vrach-current
```

Для отдельного текущего набора у capture есть `--output-dir /tmp/vrach-current`.
JSON появятся после выполнения команды оператором; подготовка скриптов не создаёт
и не подменяет контрольные результаты работающего приложения.
