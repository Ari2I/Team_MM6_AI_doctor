# Раздел «Разбор ИИ»: перенос во frontend-ветку

Раздел встроен в `ResultView` после таблицы позиций. Использует тот же стиль,
текущие React/TypeScript/Vite и существующий API-клиент. Новые зависимости,
изменения package.json/lock, Dockerfile и nginx не требуются.

## Изменённые файлы

- `src/ai-report-contract.ts`: типы обёртки `ai-report.1` и `human-report.1`,
  проверка ID заявки, строк/пар и вложенных источников; безопасные URL.
- `src/components/AIReportPanel.tsx`: чтение отчёта и отображение состояний,
  категорий/конфликтов, оснований, вопросов, действий, цитат и сумм.
- `src/ai-report.css`: стили только нового раздела, включая мобильную ширину.
- `src/api.ts`: `loadAIReport()`, общий `VITE_API_URL`, credentials и AbortSignal;
  статус 409 разрешён только при чтении AI-отчёта, означает отсутствие снимка.
- `src/components/ResultView.tsx`: подключение для `status=analyzed`.
- `tests/api.test.mjs`, `tests/ai-report*.test.mjs`, `tests/helpers/`: проверка
  контракта, API, отображения и совместимости прежней карточки/Excel.

Прототип из `.local/ai-report-preview/` не входит в перенос. Его сервер,
синтетический переключатель и копии прежних компонентов не нужны.

## Контракт и поведение

Нужен backend с `GET /applications/{id}/ai-report`:

- 200: обёртка `ai-report.1` с `human_report` и соответствующими ему `checks`.
- 409: сохранённого AI-отчёта нет; показывается отдельное сообщение.
- 401: требуется вход; 404/5xx/невалидный ответ: ошибка только внутри раздела.

Загрузка выполняется после получения карточки и при повторном открытии по
`?application=...`. При смене заявки/размонтировании чтение отменяется. Кнопка
«Повторить загрузку отчёта» повторяет GET; POST/повторного анализа не вызывает.
Карточка и Excel доступны независимо от ошибки AI-раздела. Для ещё не завершённой
или ошибочной карточки раздел не запрашивается.

Категория показывается готовым текстом `human_report.items[].category`.
Backend-справочник в сборке защиты отключён, его сравнение не показывается.
При конфликте фасада видны обе категории и предупреждение. Неопределённость,
PARTIAL, FALLBACK, необработанные пары и FORM_MISMATCH остаются явными.
COMPLETE означает обработку всех пар, а не успешность модели.

Тексты выводятся как React-текст без HTML/Markdown-инъекции. Цитаты не
пересказываются и сохраняют переносы строк. Кликабельны только абсолютные
http/https URL без встроенных логина/пароля. Ссылки на источники относятся к
конкретной паре; одинаковые номера цитат разных диагнозов не смешиваются.
Суммы показываются строками из сохранённого отчёта, без новых расчётов.

## Проверка и перенос

В корне этой версии репозитория нужен существующий `sample_api_response.json`
для тестов прежнего API. Из `frontend/`:

```bash
npm ci
npm test
npx tsc --noEmit
npm run build
```

Для финального переноса нужен отдельный frontend-коммит из `demo/28-11-ai`.
В нём находятся только файлы `frontend/`, этот документ включён. SHA коммита
передаётся отдельно после сохранения; его можно посмотреть:

```bash
git log --oneline -- frontend/src/components/AIReportPanel.tsx
```

После публикации по разрешению владельца backend фронтендер обновляет сведения
о ветках и, находясь в своей согласованной ветке с чистым деревом, выполняет
`git cherry-pick <SHA_frontend_коммита>`. Всю backend-ветку сливать ради раздела
не нужно. При конфликтах сверить `api.ts`/`ResultView.tsx`/тесты с текущим экраном,
не заменять файлы целиком и не менять контракт по догадке. Тесты/helpers переносятся
вместе с компонентом. Эта инструкция сама никаких переключений/push не выполняет.

Локально проверены 30 frontend-тестов, TypeScript и Vite production-build;
backend — 547 passed, 93 skipped (PostgreSQL и рабочий RAG-кэш), ruff без замечаний.
Production-build выполнялся с отключённым чтением .env. Зависимости и их lock
не менялись. Браузерная приёмка нового раздела и Docker-сборка выполняются
пользователем: вход, сохранённый положительный/отрицательный контроль, два диагноза,
раскрытие источников, Excel, обновление страницы, ошибка отчёта без потери карточки.
